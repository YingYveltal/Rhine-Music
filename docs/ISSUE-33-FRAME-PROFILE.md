# Issue #33：持续掉帧的第二轮定位

起点 main `9cbc751ad01fd8e569e737136506fe4f0ce65516`。旧 PR #35 的文字布局候选没有稳定收益，本分支不启用或继承该候选。当前代码只完成离线验证，**尚未证明帧率或延迟改善，也不是新的用户发行包**。

## 选择依据

上一轮在 1920×1182 原始画质下，浏览 RAF P95 44 ms、CPU 提交 P95 2 ms；扰动式主场景分段读回 18–32 ms。证据优先指向主场景/WebGL/呈现成本，不能把剩余时间全部归作 GPU。首次菜单曾有约 80 ms CPU 峰，但文字布局仅占 3 ms，需要进一步拆分。原始数据及限制仍见旧 PR #35，本轮不将不同 DPR 或旧 Metal 的完成时间拼成对照。

两个单变量候选：

- 精确边界剔除，默认关闭。现有球形边界对薄而宽的盒体较松；新路径使用六个视锥平面与变换后的盒体支撑半径，只有八个角都处于同一平面外侧才剔除。保留相机和阴影视锥并集、原始拾取编号、封面属性和排序。没有改变模型、材质、阴影尺寸、画布分辨率或动画。形变几何仍走原路径。
- 关闭既有不透明深度预绘，默认仍开启。仅用于核查当前 Apple GPU/WebKit 下额外一遍几何绘制是否值得，不预设旧优化一定有效；必须通过同姿态画面比较才能当作同画质候选。

新增测量把 presentation、菜单 HTML 构建、显示转换、滚动复位、遮罩、焦点分别记录；场景记录 update、图集提交、尺寸策略及 render 提交。嵌套 CPU 段包含子段，不能相加；回调中的工作与前一个 RAF 间隔也不是同一时间段。非测量期不读取这些细分时钟。没有增加 GPU 同步屏障到正常帧。

## 有界实测顺序（尚未执行）

由总控交接独占 GUI/GPU/构建时段后，复用已有 Cargo target 构建一次诊断包。启动既有 Preview QA 隔离身份，核对实际 WebKit store 和数据目录，使用 16 张编号合成封面与静音曲目，不连接真实账号。用户正常应用、真实曲库和音频状态不作测试操作。

先记录包源码/散列、设备、电源、实际窗口、DPR、画布和画质。原始画质、非减少动态、smoothMotion 关闭以固定像素数，双列排序。窗口若变化，保留并标记该轮无效，不跨分辨率比较。

1. 预热一轮已有 J 回放；单独保存首次菜单 CPU 结果。
2. 在暖昼/深夜架子、详情和运动中冻结姿态，以 A1/A2/B/A3 对比每个候选；图片采集与性能计时分开。A/A 与恢复应完全相同，候选最大通道差不超过 2/255，并人工检查玻璃/封面/阴影。无通过画面证据的候选不启用。
3. 每轮回到 QA01 架子，停稳 10 秒，运行同一 28 秒、111 次交互回放。先 A1/A2，再 C1/A3/C2；C 是精确边界候选。若画面通过，再 D1/A4/D2；D 仅关闭原深度预绘。不同时改变两个变量。计时期间无截图/读回/编译/其他 GPU 工作。
4. 比较帧 P50/P95/P99、>50 ms 比例、输入处理至下次提交、CPU 段及三角形数。两次候选的 P95 改善都须超过 A1/A2 自然差，并且长尾和输入指标没有一致退化，才考虑启用。无稳定收益就停该候选；首次 CPU 峰按新分段证据决定是否有值得修复的独立问题。

QA 构建 `VITE_FRAME_PROFILE_QA=1`：Ctrl+Option+C 切精确边界，D 切原深度预绘；测量中及待启动回放期间禁止切换。Y 只在 16 张 QA 库且恰好一个候选开启时生成冻结姿态原图/像素报告并恢复原状态。正常构建无这些新快捷键。J 沿用实际应用处理器回放，不是 OS 输入到光子的测量。

## 技术路线判断

继续采用 Rust 核心 + WebView/Three.js 是本轮建议，不是已证明全局最快的技术栈。已有 Metal 原型没有解决交互长尾且尚有画面差异；这不足以支持迁移。光追加速的是加速结构遍历/射线求交，需要对应渲染管线，并不是现有 WebGL 材质或 DOM 动画的通用提速开关。Apple 的 [Metal 光追指南](https://developer.apple.com/videos/play/wwdc2023/10128/)也分别讨论结构构建时间和追踪时间。本项目当前没有测得光追收益，因此本轮先减少已有管线的无用工作，而不引入另一套光照外观。
