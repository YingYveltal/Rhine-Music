# Issue #25：曲库导入与 QQ 提示

起点 `13bb2f2abd7c5f0bd39a1a85531289a7f52baf44`（已认可 Preview），本轮只改变音乐库面板及文件夹选择入口。渲染默认、音乐源后端和音频核心未改动。

## 实现

- 原生版增加“选择文件夹…”：支持系统多目录选择，只追加到当前输入，仍需点击“保存目录并扫描”。取消不改输入，重复路径（含尾部分隔符差异）不重复追加；手动输入原文保留。扫描时仍由原有 `safe_roots` 规范化路径、合并别名和检查数量。浏览器版不显示原生按钮，保留手动输入。
- 选择器返回时读取最新输入；原面板被关闭或替换则丢弃结果。单一待选状态阻止重复弹出。路径含换行或首尾空白时显示明确错误，避免被现有逐行输入错误拆分或裁剪。
- QQ 普通状态显示账户连接、保存与缓存/同步状态，保留真实错误、重新验证、保存和忘记连接。官方 Key 状态与输入放在折叠的高级设置；缓存不等于登录成功。
- 核对现有后端：搜索无 Key 时会尝试 `WebClient::search`，不会被前端新增限制；每日推荐需要 Key，点击时重新读取状态，缺少配置则展开高级设置并说明原因。没有修改 QQ 状态接口或后端。

## 原生 API 与依赖

采用 [Tauri 官方 Dialog 插件](https://v2.tauri.app/plugin/dialog/) 的 Rust API，锁定解析结果为 `tauri-plugin-dialog 2.8.1`。其 `blocking_pick_folders` 必须离开主线程，命令在 `spawn_blocking` 中运行，并设置父窗口；返回 `None` 表示取消。依据 [FileDialogBuilder API](https://docs.rs/tauri-plugin-dialog/2.8.1/tauri_plugin_dialog/struct.FileDialogBuilder.html)。

仅增加自定义 `pick_music_folders` 命令与插件初始化，没有引入前端通用文件读写权限或新扫描入口。插件传递依赖包含 `rfd`、`tauri-plugin-fs`，但没有为 JS 配置文件访问权限。现有锁定 Tauri 版本保持不变；插件最低 Rust 1.90，项目 CI 为 1.93.1。
